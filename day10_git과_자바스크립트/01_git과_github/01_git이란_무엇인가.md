# 01. Git이란 무엇인가

## 1. 우리가 지금까지 해온 방식

파일을 고치다 보면 이런 폴더가 생깁니다.

```
보고서.hwp
보고서_최종.hwp
보고서_최종_진짜최종.hwp
보고서_최종_진짜최종_교수님피드백반영.hwp
보고서_최종_이거씀.hwp
```

문제가 세 가지 있습니다.

1. **뭐가 뭔지 모른다** — `진짜최종`과 `이거씀` 중 뭐가 나중 것인가?
2. **왜 바뀌었는지 모른다** — 3번째와 4번째 사이에 무엇이 달라졌나?
3. **같이 못 한다** — 둘이 동시에 고치면 하나는 덮어써진다.

**Git은 이 세 문제를 해결하는 도구**입니다.

---

## 2. Git = 코드의 저장 기록

게임의 세이브 파일을 떠올리면 됩니다.

- 원하는 시점에 **세이브(commit)** 한다
- 세이브마다 **메모(커밋 메시지)** 를 남긴다
- 언제든 **과거 세이브로 되돌아갈(checkout)** 수 있다
- 세이브 사이에 **뭐가 바뀌었는지 볼(diff)** 수 있다

파일 이름은 언제나 `보고서.hwp` 하나입니다. 버전은 Git이 따로 기록합니다.

---

## 3. Git과 GitHub는 다른 것입니다

가장 많이 헷갈리는 부분입니다.

| | Git | GitHub |
|---|---|---|
| 정체 | 프로그램 (도구) | 웹사이트 (서비스) |
| 어디서 도나 | **내 컴퓨터** | **인터넷 서버** |
| 하는 일 | 버전 기록 | 그 기록을 온라인에 보관·공유 |
| 비유 | 카메라 | 인스타그램 |
| 대체제 | (사실상 없음) | GitLab, Bitbucket |

정리하면:

> **Git으로 기록하고, GitHub에 올린다.**

인터넷이 끊겨도 Git은 잘 돕니다. GitHub는 올릴 때만 필요합니다.

---

## 4. 왜 취업할 때 중요한가

- **거의 모든 개발 회사가 Git을 씁니다.** 안 쓰는 곳을 찾기가 더 어렵습니다.
- **GitHub 주소가 곧 포트폴리오입니다.** 이력서에 "파이썬 할 줄 압니다"라고 쓰는 것보다,
  실제로 돌아가는 코드가 올라간 저장소 주소 한 줄이 훨씬 강합니다.
- **잔디(contribution graph)** — 매일 커밋하면 초록색 칸이 채워집니다.
  꾸준히 뭔가 만들었다는 눈에 보이는 증거가 됩니다.

지난 5일간 만든 파이썬 실습 코드도 오늘 GitHub에 올릴 겁니다.

---

## 5. 꼭 알아야 할 용어 5개

지금 다 외울 필요는 없습니다. 뒤에서 직접 쳐 보면서 익힙니다.

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **repository** (레포지토리, 레포) | 저장소 | Git이 관리하는 프로젝트 폴더 하나 |
| **commit** (커밋) | 저장 시점 | "여기까지 완성" 하고 찍는 스냅샷 |
| **push** (푸시) | 밀어올리기 | 내 컴퓨터 → GitHub 로 보내기 |
| **pull** (풀) | 당겨오기 | GitHub → 내 컴퓨터 로 가져오기 |
| **branch** (브랜치) | 가지 | 원본을 건드리지 않고 따로 작업하는 갈래 |

## 6. 전체 그림

```
   [ 내 컴퓨터 ]                          [ GitHub ]

   작업 폴더
   (파일 수정)
       |
       |  git add
       v
   스테이지          ← "이번 커밋에 포함할 것" 담아두는 장바구니
       |
       |  git commit
       v
   로컬 저장소  ──── git push ────>   원격 저장소
   (.git 폴더)  <─── git pull ─────   (github.com/내아이디/레포)
```

이 그림 하나가 오늘 Git 파트의 전부입니다.
`add → commit → push`, 이 세 단계가 90% 입니다.
