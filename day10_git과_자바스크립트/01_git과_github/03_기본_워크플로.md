# 03. 기본 워크플로 — add · commit · log

> 이 문서는 **직접 따라 치면서** 보는 문서입니다. 눈으로만 읽으면 남지 않습니다.

바탕화면에 연습용 폴더를 하나 만듭니다.

```bash
cd Desktop
```


## 1. `git init` — 저장소 시작하기

```bash
git init
```

```
Initialized empty Git repository in C:/Users/사용자/Desktop/git-practice/.git/
```

이 순간 폴더 안에 **`.git`** 이라는 숨김 폴더가 생깁니다.
여기에 모든 기록이 저장됩니다.

- `.git` 폴더를 지우면 **모든 버전 기록이 사라집니다.** 절대 지우지 마세요.
- 확인하려면: `ls -a` (Windows PowerShell은 `dir -Force`)

> ⚠️ **주의**: 바탕화면이나 `C:\Users\내이름` 같은 상위 폴더에서 `git init` 하지 마세요.
> 그 아래 모든 파일이 관리 대상이 되어 감당이 안 됩니다.
> **프로젝트 폴더 하나 = 저장소 하나** 입니다.

## 2. 파일 만들고 `git status` 로 상태 보기

파일을 하나 만듭니다.

```bash
echo "# 내 첫 저장소" > README.md
```

이제 Git에게 물어봅니다. **`git status` 는 가장 자주 쓰는 명령어입니다.**
막히면 일단 이걸 치세요.

```bash
git status
```

```
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        README.md

nothing added to commit but untracked files present
```

`Untracked files` = "이 파일 새로 생겼는데, 관리할까요?" 라는 뜻입니다.

---

## 3. 파일의 4가지 상태

이 그림이 Git의 핵심입니다.

```
 Untracked        Modified          Staged          Committed
 (새 파일)   →   (수정됨)     →   (담김)      →    (저장됨)
              git add        git add        git commit
```

| 상태 | 색 (git status) | 뜻 |
|---|---|---|
| **Untracked** | 빨강 | Git이 아직 모르는 새 파일 |
| **Modified** | 빨강 | 관리 중인데 내용이 바뀐 파일 |
| **Staged** | 초록 | 이번 커밋에 포함하기로 담아둔 파일 |
| **Committed** | (안 보임) | 저장 완료. 깨끗한 상태 |

**Staged(스테이지)** 는 장바구니입니다.
마트에서 물건을 카트에 담고(`add`) → 계산(`commit`) 하는 것과 같습니다.
바꾼 파일이 10개여도 그중 3개만 담아서 커밋할 수 있습니다.

## 4. `git add` — 장바구니에 담기

```bash
git add README.md
```

```bash
git status
```

```
Changes to be committed:
        new file:   README.md
```

초록색으로 바뀌었습니다. 담겼다는 뜻입니다.

### 전부 담기

```bash
git add .
```

`.` 은 "현재 폴더의 모든 변경사항" 입니다. 실무에서 제일 많이 씁니다.

> ⚠️ `git add .` 은 편하지만 위험합니다.
> **비밀번호가 든 `.env`, 100MB짜리 동영상**까지 같이 담길 수 있습니다.
> 담기 전에 항상 `git status` 로 목록을 확인하는 습관을 들이세요.

### 잘못 담았을 때 빼기

```bash
git restore --staged README.md
```

## 5. `git commit` — 저장하기

```bash
git commit -m "README 파일 추가"
```

```
[main (root-commit) 3f2a1b9] README 파일 추가
 1 file changed, 1 insertion(+)
 create mode 100644 README.md
```

- `-m` 은 message 의 약자입니다. 뒤에 **커밋 메시지**를 씁니다.
- `-m` 을 빼먹으면 낯선 에디터 화면이 열립니다.
  당황하지 말고 `:q` 를 치고 Enter (vim 종료) → 다시 `-m` 붙여서 실행하세요.

### 좋은 커밋 메시지

커밋 메시지는 **미래의 나에게 쓰는 메모**입니다.
6개월 뒤의 내가 읽는다고 생각하고 쓰세요.

| ❌ 나쁜 예 | ✅ 좋은 예 |
|---|---|
| `수정` | `로그인 실패 시 에러 메시지 표시` |
| `ㅁㄴㅇㄹ` | `미세먼지 API 호출 함수 추가` |
| `최종` | `학생 성적 정렬 기준을 이름순에서 점수순으로 변경` |
| `버그 고침` | `점수가 0일 때 등급이 F가 아닌 A로 나오던 버그 수정` |

규칙 하나만 기억하세요. **"무엇을 왜 바꿨는지"** 를 씁니다.

## 6. 수정 → 커밋 반복해 보기

이제 사이클을 한 번 더 돌려 봅니다.

```bash
echo "파이썬 특강 실습 저장소입니다." >> README.md
```

```bash
git status
```

이번엔 `Untracked` 가 아니라 **`modified: README.md`** 로 나옵니다.
Git이 이미 아는 파일이기 때문입니다.

### 뭐가 바뀌었는지 보기

```bash
git diff
```

```
+파이썬 특강 실습 저장소입니다.
```

- `+` 는 추가된 줄, `-` 는 삭제된 줄입니다.
- 화면이 길면 `q` 를 눌러 빠져나옵니다.

### 담고 저장

```bash
git add .
```

```bash
git commit -m "README에 저장소 설명 추가"
```

## 7. `git log` — 기록 보기

```bash
git log
```

```
commit 8d4c1f2... (HEAD -> main)
Author: 홍길동 <hong@example.com>
Date:   Fri Aug 14 14:20:11 2026 +0900

    README에 저장소 설명 추가

commit 3f2a1b9...
Author: 홍길동 <hong@example.com>
Date:   Fri Aug 14 14:15:02 2026 +0900

    README 파일 추가
```

- 최신 커밋이 **위**에 옵니다.
- `commit` 뒤의 긴 문자열이 **커밋 해시** — 그 커밋의 주민번호입니다.
- 화면이 길면 `q` 로 나옵니다.

### 한 줄로 간단히 (훨씬 자주 씀)

```bash
git log --oneline
```

```
8d4c1f2 (HEAD -> main) README에 저장소 설명 추가
3f2a1b9 README 파일 추가
```

## 8. 되돌리기 — 자주 쓰는 3가지

| 상황 | 명령어 |
|---|---|
| 파일을 고쳤는데 **없던 일로** 하고 싶다 (아직 add 전) | `git restore 파일명` |
| **add 를 취소**하고 싶다 (아직 commit 전) | `git restore --staged 파일명` |
| **직전 커밋 메시지를 고치고** 싶다 | `git commit --amend -m "새 메시지"` |

> `git restore` 로 되돌린 내용은 **복구할 수 없습니다.** 실행 전 한 번 더 생각하세요.
> 반대로 이미 **커밋한 것은 웬만하면 복구됩니다.** 그래서 자주 커밋하는 게 안전합니다.

## 9. `.gitignore` — 올리면 안 되는 것

일부 파일은 **절대 Git에 담기면 안 됩니다.**

- `.env` — API 키, 비밀번호 (5일차에서 배웠습니다)
- `venv/` — 가상환경 폴더. 용량만 크고 남이 받아도 못 씀
- `__pycache__/` — 파이썬이 자동 생성하는 캐시
- `.DS_Store` (mac), `Thumbs.db` (Windows) — OS 쓰레기 파일

프로젝트 폴더에 **`.gitignore`** 라는 파일을 만들고 아래를 적습니다.

```
# 환경변수
.env

# 파이썬
venv/
__pycache__/
*.pyc

# OS
.DS_Store
Thumbs.db
```

이제 `git add .` 를 해도 이 파일들은 담기지 않습니다.

> **중요**: `.gitignore` 는 **커밋되기 전**에 만들어야 효과가 있습니다.
> 이미 커밋된 `.env` 는 `.gitignore` 에 넣어도 계속 추적됩니다.
> 그럴 땐 `git rm --cached .env` 로 먼저 추적을 해제하세요.

## 정리 — 오늘 외울 5줄

```bash
git status                    # 지금 상태 확인 (막히면 무조건 이것부터)
git add .                     # 변경사항 담기
git commit -m "메시지"         # 저장
git log --oneline             # 기록 보기
git diff                      # 뭐가 바뀌었는지 보기
```
