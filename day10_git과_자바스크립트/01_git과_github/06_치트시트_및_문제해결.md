# 06. 치트시트 & 자주 만나는 에러

인쇄해서 모니터 옆에 붙여두세요.

## 명령어 치트시트

### 시작

```bash
git init                                # 새 저장소 시작
git clone <URL>                         # 기존 저장소 받아오기
```

### 매일 쓰는 것

```bash
git status                              # 상태 확인 (막히면 무조건 이것)
git add .                               # 모든 변경사항 담기
git add <파일>                           # 특정 파일만 담기
git commit -m "메시지"                   # 저장
git push                                # GitHub에 올리기
git pull                                # GitHub에서 받아오기
```

### 확인

```bash
git log --oneline                       # 커밋 기록 한 줄씩
git log --oneline --graph --all         # 브랜치까지 그림으로
git diff                                # 아직 add 안 한 변경사항
git diff --staged                       # add 한 변경사항
git show <커밋해시>                      # 특정 커밋 상세
```

### 브랜치

```bash
git branch                              # 브랜치 목록
git switch -c <이름>                     # 만들고 이동
git switch <이름>                        # 이동
git merge <이름>                         # 현재 브랜치에 합치기
git branch -d <이름>                     # 삭제
git push -u origin <이름>                # 브랜치를 GitHub에 올리기
```

### 되돌리기

```bash
git restore <파일>                       # 수정 취소 (add 전)
git restore --staged <파일>              # add 취소 (commit 전)
git commit --amend -m "새 메시지"        # 직전 커밋 메시지 수정
git revert <커밋해시>                    # 그 커밋을 취소하는 새 커밋 생성 (안전)
git merge --abort                       # merge 중단
```

### 원격

```bash
git remote -v                           # 연결된 주소 확인
git remote add origin <URL>             # 주소 연결
git remote set-url origin <URL>         # 주소 변경
```

## 자주 만나는 에러 10가지

### 1. `fatal: not a git repository`

```
fatal: not a git repository (or any of the parent directories): .git
```

**원인**: Git 저장소가 아닌 폴더에서 git 명령을 쳤다.
**해결**: `pwd` 로 위치 확인 → 맞는 폴더로 `cd` 하거나, 새 저장소면 `git init`

---

### 2. `Please tell me who you are`

```
*** Please tell me who you are.
```

**원인**: 이름/이메일 설정을 안 했다.
**해결**:
```bash
git config --global user.name "이름"
```
```bash
git config --global user.email "이메일"
```

---

### 3. `failed to push some refs` / `fetch first`

```
! [rejected]        main -> main (fetch first)
```

**원인**: GitHub에 내가 모르는 커밋이 있다.
**해결**:
```bash
git pull
```
그 뒤 다시 `git push`

---

### 4. `remote origin already exists`

**원인**: 이미 origin이 연결되어 있다.
**해결**: 주소를 바꾸고 싶으면
```bash
git remote set-url origin <새 URL>
```

---

### 5. `src refspec main does not match any`

**원인**: **커밋이 하나도 없는데** push 했다.
**해결**: `git add .` → `git commit -m "..."` 먼저.

---

### 6. 낯선 검은 화면에 갇혔다 (vim)

`git commit` 을 `-m` 없이 쳤을 때 발생합니다.

**탈출**: `Esc` → `:q!` → `Enter`
저장하고 나가려면 `Esc` → `:wq` → `Enter`

`git log` 나 `git diff` 중이라면 그냥 **`q`** 한 글자.

---

### 7. Authentication failed

```
remote: Support for password authentication was removed
```

**원인**: 비밀번호로 로그인하려 했다.
**해결**: 02번 문서의 **PAT(Personal Access Token)** 을 만들어 비밀번호 자리에 붙여넣기.

---

### 8. `.env` 를 실수로 커밋했다

```bash
git rm --cached .env
```
```bash
echo ".env" >> .gitignore
```
```bash
git commit -m ".env 추적 제거"
```

> ⚠️ 이미 **push까지 했다면 키가 유출된 것**입니다.
> 반드시 해당 API 키를 **폐기하고 새로 발급**받으세요. 기록에서 지워도 늦습니다.

---

### 9. 커밋했는데 잔디가 안 심어진다

**원인**: 커밋에 쓰인 이메일이 GitHub 계정 이메일과 다르다.
**확인**:
```bash
git config user.email
```
**해결**: GitHub 계정에 등록된 이메일로 다시 설정. (이후 커밋부터 적용)

---

### 10. 한글 파일명이 `\355\225\234` 처럼 깨진다

```bash
git config --global core.quotepath false
```

## 막혔을 때 순서

1. **`git status`** — 90%는 여기에 답과 다음 명령어가 적혀 있습니다.
2. 에러 메시지를 **끝까지 읽습니다.** Git은 친절한 편이라 해결책을 같이 알려줍니다.
3. 에러 메시지를 **그대로 복사해서** 검색하거나 AI에게 물어봅니다.
4. 그래도 안 되면 — **폴더를 통째로 복사해 백업**해 두고 시도하세요.
   최악의 경우 새로 `clone` 받아 파일만 옮겨넣으면 됩니다.
